# Proposed Stage II development-standard and future-work amendment

Prepared 3 November 2026. Proposal ID:
`pact-stage2-documented-exclusions-amendment-001`.
Status: **INACTIVE PROPOSAL for review. Not an execution plan.**

## Decision requested

Replace the proposed child’s blanket semantic-overlap acceptance prerequisite
with a narrower **documented-exclusion-screened development** standard. Retain
actual source integrity, protections, deterministic lexical checks and all concrete
candidate-specific unresolved cases as hard gates. Accept residual unknown semantic
contamination and missing-history compliance as stated limitations, rather than
certify them absent. Request a finite new allowance for future physical work,
explicitly separate from unknown historical consumption.

This is a methodological change. The user authorized preparing it and its CPU
implementation; this specific text and allowance have not yet been accepted.
The user's previous acceptance of conditional scope for further review remains
valid, but is not represented as approval of the broader change here.

## 1. Exact change in the source standard

| Existing proposed standard | New proposed child standard |
|---|---|
| Requires current `material_overlap_review=no_unresolved_cases` before candidate selection | Does not require a blanket semantic review; reports semantic contamination as unverified |
| Full prior-coverage acceptance must clear the original gate | Uses documented source-bound exclusions under the accepted conditional original-contract scope; does not certify universal project freshness |
| Unknown historical spending prevents the old execution gate from passing | Remains unknown and disclosed; a separately accepted new future allowance would own new physical work |

This does **not** mean “any unknown is allowed.” Retain these requirements:

- Actual official pinned bytes, source-use evidence, source/answer mapping and
  historical partition verification. No new download is required if existing
  evidence applies.
- All Diamond, reserve, historical, integrity, recorded-preview and executed
  source exclusions, propagated through the existing deterministic lexical
  components and cross-source checks. No protected release or quota reduction.
- Existing 960 ARC/LogiQA allocations and prior recorded selections remain excluded.
  Import/copying is not falsely called model consumption.
- Unknown mappings, concrete candidate-specific exposure, known material-overlap
  cases and unknown exclusion reason codes remain unresolved; they cannot be
  cleared merely because a broad semantic review is no longer mandatory.
- Exactly 64 GPQA Main groups and 64 original English LogiQA groups, selected by
  the unchanged outcome-independent selector and option permutation. No fallback,
  reroll, difficulty filtering or baseline-support gate.

The relaxed conditions are **absence of blanket review** and the explicitly scoped
missing-interval assumption, not known contradictory evidence. Existing reviewers'
findings and known cases remain binding. A failure to establish actual source or
exclusion facts still stops candidate selection.

Required description in every future result:

> Exploratory development evaluation screened against documented project
> exclusions and deterministic lexical overlap. Semantic contamination, model
> pretraining exposure, and compliance during the missing historical interval
> are not established. This is not a certified fresh or untouched final-test cohort.

Freshness flags from the old child must never be forged to implement this proposal.
The old v3 infeasibility record, GPQA v2 policy and completed Stage I results stay
unchanged. A separately versioned child must carry this limitation and policy hash
through audit, plan, exports and analysis.
